# Baseline, 2026-11-10

What loads and what passes on the fork as copied from upstream (`master` = 9fbc2fd, 2020-04-13), before any code change. Recorded on Windows 11 with Unity 6000.3.23f1 and 6000.6.0f1 on Mono, API compatibility ".NET Framework", and .NET Framework 4.8 for the compiler suite. No test was edited, skipped or deleted.

How to reproduce:

- Compiler suite, no Unity: `powershell -File "Tools~/clr-tests/run.ps1"` (results in `.build/clr-tests.tsv`).
- Arcadia's tests in Unity batchmode: `powershell -File "Tools~/headless/new-harness-project.ps1"` once, then `powershell -File "Tools~/headless/run-arcadia-tests.ps1"`. Pass `-Unity <path to Unity.exe>` and `-Project <folder>` for another editor version.

## Loading in Unity 6

| Editor | Unchanged `master` | Notes |
|---|---|---|
| 6000.3.23f1 | Compiles, "Arcadia Started!" | Needs the uGUI package (`com.unity.ugui`): the hook components use `UnityEngine.EventSystems`. A bare `-createProject` project lacks it; Unity's usual templates include it. |
| 6000.6.0f1 | Does not compile | One error: `Object.GetInstanceID()` is obsolete-as-error (`Components/ArcadiaBehaviour.cs:480`). Fixed on branch `unity6/compile-6000.6` (uses `GetEntityId`, which exists from 6000.3); then Arcadia starts. |

Both editors also log that `Infrastructure/Ionic.Zip.dll.meta` uses `PluginImporter` serializedVersion 1, below the supported minimum (2). It imports anyway; re-saving the meta would clear it.

The API compatibility warning from upstream issue #391 fires on Unity 6: `Editor/ArcadiaProjectInitialization.cs` compares with `ApiCompatibilityLevel.NET_4_6`, and 6000.6 reports the ".NET Framework" level under that same enum name, so the check passes there. It still warns, wrongly worded, on ".NET Standard 2.1". Not yet tested whether Arcadia works on ".NET Standard 2.1".

## Arcadia's own tests (`Tests/arcadia/arcadia_tests.clj`)

Five groups on the async harness in `Source/arcadia/internal/test.clj`, run in batchmode edit mode.

| Editor | Pass | Fail | Error | Complete? |
|---|---|---|---|---|
| 6000.3.23f1, unchanged | 77 | 0 | 0 | No: some tests wait for Play-mode frames |
| 6000.6.0f1, with the compile fix | 76 | 1 | 0 | No: same |

- **Never finish in batchmode edit mode:** tests that schedule work with `:frames` (player frames) never get them, so their assertions don't run: `cmpt-` "Removes all attached Components...", `update-state`, `hook+`, `multiarg-test`. They are pending, not failing. Running them needs the runner to enter Play mode, probably with domain reload off so Clojure state survives.
- **The 6000.6 failure:** `core-namespace / instantiate / "3-ary instantiate uses new rotation"`. Both quaternions print as `(0.00873, 0.00663, 0.00226, 0.99994)` but aren't bit-equal; the test uses exact `=`. The rotation comes from `(rand)`, so it may be flaky on any version rather than a 6000.6 change. Making it approximate is a test change and waits for Austin's OK.

Full output: `.build/arcadia-tests-6000.3.txt`, `.build/arcadia-tests-6000.6.txt` (not committed).

## Bundled compiler suite (`Source/clojure/test_clojure`) on .NET Framework 4.8

55 namespaces against `Infrastructure/Clojure.dll` (ClojureCLR 1.10, built 2019 for Mono), run through `clojure.main` like ClojureCLR's own `run_test.clj`. 16,932 assertions pass, 1 fails, 2 error.

| Status | Count | Namespaces |
|---|---|---|
| ok | 47 | everything not listed below |
| failures | 2 | `metadata` (1 fail: `*loading-verbosely*`, `*loaded-libs*`, `*pending-paths*`, `clojure.clr.io/do-copy` have docstrings but no `:added`), `serialization` (2 errors: binary-serializing a function can't find the dynamic `eval` assembly on deserialize) |
| load-error | 6 | `attributes` (`foo.Bar`), `compilation` (`line_number_examples.clj.dll`), `genclass` (`ExampleClass`), `try-catch` (`Clojure.Tests.dll`): need test-helper assemblies that ClojureCLR's own build makes and Arcadia doesn't ship. `clojure-xml`: no such namespace in this tree. `rt`: `NullReferenceException` while loading (earlier "Can't dynamically bind non-dynamic var print-initialized"). |

Per-namespace counts: `docs/baseline/2026-11-10-clr-tests.tsv`.

Two host quirks worth knowing: `spit` in this ClojureCLR doesn't truncate an existing file (the runner deletes first), and the first host version ran tests outside `clojure.main`'s bindings, which produced false failures in `reader`, `repl` and `rt`.

## What this means

- Arcadia's Clojure side works on Unity 6 Mono as-is. The 2019 compiler loads and passes its suite on .NET Framework 4.8 and inside Unity 6's Mono.
- The C# side needed one change for 6000.6 and a uGUI dependency.
- Not yet covered: the socket REPL and nREPL accepting a connection, Play mode, player builds (export).
