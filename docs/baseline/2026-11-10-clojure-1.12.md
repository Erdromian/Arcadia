# ClojureCLR 1.12.6 swap, 2026-11-10

Branch `unity6/clojure-1.12` replaces the committed 2019 ClojureCLR 1.10 binaries with upstream 1.12.6, fetched by `Tools~/build-runtime/build.ps1` from NuGet's `net462` build with every package pinned by hash (`packages.lock.json`, restored in locked mode). Compare with `2026-11-10-baseline.md`.

| Arcadia tests, Unity 6000.3.23f1 | 77 pass, 0 fail | 76 pass, 1 fail |
| Arcadia tests, Unity 6000.6.0f1 (with compile fix) | 76 pass, 1 fail | 76 pass, 1 fail |

- The one Arcadia failure is the same test in every 1.12 run and in the 1.10 run on 6000.6: `instantiate` with a random rotation, compared with exact `=`. It passed once (1.10 on 6000.3) and failed three times, so it looks flaky rather than tied to an editor or runtime. Changing it to an approximate comparison is a test change and waits for Austin.
- Play-mode-frame tests stay pending in batchmode, as before.
- Compiler suite on 1.12.6: the 1 error reads a file relative to upstream's own test folder. The 8 namespaces that don't load need helper assemblies upstream builds before testing (`attributes`, `compilation2`, `genclass`, `param-tags`, `try-catch`), are JVM-only (`clearing`), don't exist (`clojure-xml`), or expect `clojure.repl` preloaded (`repl`). Per-namespace counts: `2026-11-10-clr-tests-1.12.6.tsv`.
- Startup: ClojureCLR 1.12 is up in about 3 s on .NET 4.8; `arcadia.core` loads in about 2 s and `arcadia.linear` in about 3 s under Unity's Mono.

## What had to change

Two ClojureCLR 1.12 compiler regressions, both reproduced on .NET Framework 4.8 and on Unity's Mono, with Arcadia workarounds in `a3fad99`:

1. **Nested `Type/method` calls compile in exponential time.** Each extra level of nesting doubles compile time: 5.4 s at depth 14 for `UnityEngine.Vector2/op_Addition`, versus 4 ms at depth 19 on 1.10. The explicit `(. Type method args)` form stays flat. `arcadia.linear`'s `def-vop-lower` nests up to 20 deep, so `(require 'arcadia.linear)` ran for over an hour. `nestl` now emits the dot form.
2. **`params` array overloads.** `(Array/CreateInstance System.Object 2)` picks `CreateInstance(Type, params long[])` and throws `InvalidCastException` (Int64 to Int64[]). `lit-array` now passes `(int n)`. This broke every `reify-variadic-ifn`, which the test harness uses for its testers.

Repros and version ranges are written up in `docs/upstream-reports/`. They were not filed upstream (Austin, 2026-11-10); the fork keeps its workarounds.

Runtime packaging:

- 1.12 finds library sources (spec, tools.reader) embedded in DLLs that are already loaded. Unity loads every managed DLL under `Assets/`, so this works without extra code.
- `Clojure.dll` 1.12 is strong-named. Anything compiled against the unsigned 1.10 `Clojure.dll` (the old test-only libraries) can't bind to it, so those were removed.
- Unity 6000.6 provides `System.Runtime.CompilerServices.Unsafe` and `Microsoft.Bcl.AsyncInterfaces` to plugins; 6000.3 doesn't, and then rejects `System.Text.Json` and, through it, `Clojure.dll`. Both are shipped. No duplicate-assembly warnings on 6000.6.
- `Source/clojure` (the 1.10 library sources and test suite) is gone: on the load path it would shadow 1.12's embedded namespaces.
