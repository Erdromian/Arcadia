# ClojureCLR 1.12.6 swap, 2026-11-10

Branch `unity6/clojure-1.12` replaces the committed 2019 ClojureCLR 1.10 binaries with upstream 1.12.6, fetched by `Tools~/build-runtime/build.ps1` from NuGet's `net462` build with every package pinned by hash (`packages.lock.json`, restored in locked mode). Compare with `2026-11-10-baseline.md`.

## Results

| Check | 1.10 (baseline) | 1.12.6 |
|---|---|---|
| Arcadia tests, Unity 6000.3.23f1 | 77 pass, 0 fail | 76 pass, 1 fail |
| Arcadia tests, Unity 6000.6.0f1 (with compile fix) | 76 pass, 1 fail | 76 pass, 1 fail |
| Compiler suite on .NET Framework 4.8 | own 1.10 suite: 47/55 ns ok, 16,932 pass, 1 fail, 2 error | upstream 1.12.6 suite: 56/65 ns ok, 17,704 pass, 0 fail, 1 error |

- The one Arcadia failure is the same test in every 1.12 run and in the 1.10 run on 6000.6: `instantiate` with a random rotation, compared with exact `=`. It has passed and failed on the same editor and runtime (on 1.12 it passed in 3 of 7 runs), so it is flaky rather than tied to an editor or runtime. Changing it to an approximate comparison is a test change and waits for Austin.
- Tests that wait on Play-mode frames never finish in batchmode edit mode, so the harness never sees the run complete. The runner now stops once results have been unchanged for 20 s (`-arcadiaQuiet`) and lists the testers still open: `cmpt-system / cmpt- / Removes all attached Components...`, `hook-state-system / multiarg-test` and `hook-state-system / role system / role+`. Such a run exits 5 ("everything that ran passed, some tests pending") rather than 0, and takes about a minute instead of waiting out the 10-minute timeout. Same 3 on 6000.3 and 6000.6.
- Compiler suite on 1.12.6: the 1 error reads a file relative to upstream's own test folder. The 8 namespaces that don't load need helper assemblies upstream builds before testing (`attributes`, `compilation2`, `genclass`, `param-tags`, `try-catch`), are JVM-only (`clearing`), don't exist (`clojure-xml`), or expect `clojure.repl` preloaded (`repl`). Per-namespace counts: `2026-11-10-clr-tests-1.12.6.tsv`.
- Startup: ClojureCLR 1.12 is up in about 3 s on .NET 4.8; `arcadia.core` loads in about 2 s and `arcadia.linear` in about 3 s under Unity's Mono.

## What had to change

Two ClojureCLR 1.12 compiler regressions, both reproduced on .NET Framework 4.8 and on Unity's Mono, with Arcadia workarounds in `a3fad99`:

1. **Nested `Type/method` calls compile in exponential time.** Each extra level of nesting doubles compile time: 5.4 s at depth 14 for `UnityEngine.Vector2/op_Addition`, versus 4 ms at depth 19 on 1.10. The explicit `(. Type method args)` form stays flat. `arcadia.linear`'s `def-vop-lower` nests up to 20 deep, so `(require 'arcadia.linear)` ran for over an hour. `nestl` now emits the dot form.
2. **`params` array overloads.** `(Array/CreateInstance System.Object 2)` picks `CreateInstance(Type, params long[])` and throws `InvalidCastException` (Int64 to Int64[]). `lit-array` now passes `(int n)`. This broke every `reify-variadic-ifn`, which the test harness uses for its testers.

Repros and version ranges are written up in `docs/upstream-reports/`. They were not filed upstream (Austin, 2026-11-10); the fork keeps its workarounds.

Runtime packaging:

- 1.12 finds library sources (spec, tools.reader) embedded in DLLs that are already loaded. Unity loads every managed DLL under `Assets/`, so this works without extra code.
- `Clojure.dll` 1.12 is strong-named. Anything compiled against the unsigned 1.10 `Clojure.dll` (the old test-only libraries) can't bind to it, so those were removed.
- Unity 6000.6 provides `System.Runtime.CompilerServices.Unsafe` and `Microsoft.Bcl.AsyncInterfaces` to plugins; 6000.3 doesn't, and then rejects `System.Text.Json` and, through it, `Clojure.dll`. Both are shipped. No duplicate-assembly warnings on 6000.6.
- `Source/clojure` (the 1.10 library sources and test suite) is gone: on the load path it would shadow 1.12's embedded namespaces.

## REPLs

The harness now checks both REPL servers after the tests (`Tests/Editor/ReplProbe.cs`): it connects to the socket REPL on `localhost:37220` and nREPL on `127.0.0.1:3722` and evaluates `(+ 1 2)` and `(UnityEngine.Application/unityVersion)`, which runs on Unity's main thread. All five checks pass on 6000.3 and 6000.6 after one fix:

- 1.12 refers `clojure.core` into `user` only from `RT.Init()`, which Arcadia never called, so every eval in a new REPL session failed with "Unable to resolve symbol: +". Arcadia now calls `RT.PostBootstrapInit()`, the part of `RT.Init()` that sets up `user` (and loads `user.clj` and any `clojure.server.*` servers, as Clojure does). It skips the rest of `RT.Init()`, which re-loads the spec DLLs Unity has already loaded and turns on macro spec checks, which Arcadia turns off.
- The socket REPL binds the first address `localhost` resolves to, `::1` on Windows, so clients must connect to `localhost` (as Arcadia's `repl-client` scripts do), not `127.0.0.1`.

## Player builds

`Tools~/headless/run-player-smoke.ps1` builds a Windows x64 Mono player from the harness project and runs it headless (`Tests/Editor/HeadlessPlayerBuild.cs`). The build step copies `Tests/headless/player/player_smoke.clj` into the project, lists it in `Assets/configuration.edn`'s `:export-namespaces`, makes a scene with a `:start` hook and state `{:n 42 :s "kept"}` on one GameObject, runs Arcadia's "Prepare for Export" and builds. In the player the hook logs its checks and quits. Both editors work with no changes to Arcadia:

```
6000.6.0f1  build Succeeded, 118 MB  ARCADIA-PLAYER-SMOKE {:clojure "1.12.6", :linear "(2.00, 3.00, 4.00)", :state {:n 42, :s "kept"}, :string "OK", :editor? false}
6000.3.23f1 build Succeeded, 112 MB  (same line)
```

So in a player, AOT-compiled namespaces load, hooks fire, scene state survives serialization, and `arcadia.linear` and `clojure.string` work.

- The export compiles Arcadia's namespaces, the smoke namespace, and `clojure.spec.alpha`/`clojure.spec.gen.alpha` to `.clj.dll`. That's right: 1.12's `clojure.spec.alpha.dll` holds spec only as embedded source, so without the export the player would compile spec at startup. `Clojure.dll` namespaces are never recompiled, because 1.12's `load` finds their compiled init types first.
- Seen but not changed: changing `configuration.edn` makes Arcadia's config listener call `clojure.core.server/start-server` again on the port already in use, which logs a `SocketException` from the new server's thread; the first server keeps working. And the player logs Unity 6's deprecation notice for `OnLevelWasLoaded` (`OnLevelWasLoadedHook`).
